Design — Section 2: Backend

Two changes: expand the option mapper, add one new endpoint.

① Expand _build_options() in auto_pattern_maker.py

The existing _DESIGN_OPTION_MAP only covers 5 designs shallowly. We expand it to cover all 15, and we add a source tag per option so the frontend knows which values came from AI vs. defaults.

Design Option key Mapped from Vision field Source
simon / simone collarStyle components.collar.type → classic / band / none ai
simon / simone cuffStyle components.sleeves.cuff_type → classical / frenchCuff ai
huey / hugo kangarooPocket components.pockets.type != 'none' → true/false ai
carlita / carlton pockets components.pockets.type != 'none' → true/false ai
sandy / waralee waistbandWidth cut.waist_treatment → 30mm elastic / 40mm dart ai
paco / titan elasticWidth cut.waist_treatment == 'elastic' → 25mm, else 0 ai
all designs sa craft_recommendations.seam_allowance_mm (Claude suggests this) ai
all designs paperless always false (user can toggle in panel) default

Each option entry gets a source: "ai" | "default" field. The frontend uses this to render gold borders on AI-sourced options.

③ New endpoint

GET  /analyses/{analysis_id}/draft-params?profile_id={uuid}
• Reads ai_analyses row (already exists) — no new DB table
• Reads body_profiles measurements (mm) for the profile
• Calls build_draft_params(measurements_mm, analysis_result)
• Returns DraftParamsResponse above
• If analysis not found → 404. If profile not found → uses empty measurements + returns warning.
